## Ejecutar de forma reproducible

Node **24.19.0** (`.node-version` / `.nvmrc`), pnpm **11.25.0** (`packageManager`). Instalar esos ejecutables desde sus distribuciones oficiales o usar el runtime ya disponible; no se instala nada globalmente desde este proyecto.

```sh

```

Abrir **http://127.0.0.1:8765/experimental/recogidas/**. La descarga de Chromium solo es necesaria una vez para usar el navegador asociado al Playwright fijado. Alternativa ya verificada en este equipo: `TAMAGO_BROWSER_CHANNEL=chrome pnpm test:browser`, usando Chrome instalado; su versión no queda fijada por el lockfile. Para reproducir el navegador del runner, usar Chromium de Playwright. No se descargó ese navegador en esta entrega.

La instalación ignora scripts de dependencias mediante `.npmrc`; los binarios por plataforma de esbuild/Biome se resuelven mediante paquetes fijados. El build genera un validador standalone de Ajv y un bundle local: no hay CDN ni dependencia de red al capturar. No hay CI ni workflow de despliegue nuevo.

La fuente del experimento es `src/offline/`; `dist/experimental/recogidas/` es salida reproducible de build, no otra implementación. No editar la salida a mano. El build no toca los archivos de DEV-001. Los tests se ejecutan con perfiles temporales y datos sintéticos.

## Recorrido observable

1. Abrir con red y esperar «Pantalla preparada…». El service worker comprueba sus recursos; un fallo no muestra preparación exitosa. Primera visita sin preparación no está soportada.
2. Desconectar. Elegir origen, fecha/hora colombianas, ocurrencia 1–3 y cantidad entera. Cero explícito es válido; ausencia permanece sin información.
3. Guardar. La confirmación solo aparece después de `transaction.done`; evento y outbox se escriben juntos. Reintentar sin cambiar formulario conserva el ID y contenido del intento.
4. Cerrar navegador y volver a abrir la misma dirección/perfil sin red. Verificar el mismo ID, contenido y pendiente. No se requiere completar tres recogidas para conservar una o dos reales.
5. Exportar dos veces: el JSON conserva evento y estado y no modifica la cola. Recuperar el archivo en un espacio experimental vacío o en el mismo: idéntico ID/contenido no agrega otro evento. Mismo ID con otro contenido o misma ocurrencia con otro ID se rechaza sin sobrescribir. Un paquete se aplica por completo o se revierte.

No hay envío ni acuse. Todas las capturas son **provisionales**, incluso antes de 24 h, porque este experimento no autentica ni tiene servidor. La antigüedad superior a 24 h se avisa según reloj local y nunca impide nuevas capturas. Autor y empresa son declaraciones ficticias, no acceso concedido. El UUID de instalación identifica una copia del navegador, no acredita hardware ni usuario.

## Contrato único y compatibilidad

La forma canónica está en `contracts/collection-export.v1.schema.json`, draft-07, versión técnica **1**. Contiene el evento y el sobre de exportación mediante referencias internas. El generador no descarga referencias remotas. `src/offline/contract.mjs` añade las invariantes semánticas verificadas: timestamps reales, día colombiano coincidente con ocurrencia y ausencia de IDs/ocurrencias duplicados dentro del paquete. El mismo validador generado se usa al crear, guardar, leer, exportar y restaurar; no coacciona, rellena ni borra campos del paquete importado.

Campos obligatorios, propiedades extra rechazadas y sin `null`: ID UUIDv4, empresa/lote/galpón sintéticos, fecha operativa, zona Colombia, hora del hecho y captura, ocurrencia, huevos enteros seguros, autor declarado y nivel de acreditación, instalación declarada, versión/tipo, provisional y pendiente. El origen diario se deriva de empresa+lote+galpón+fecha; ocurrencia distingue los hechos intradía. No se asigna otro origen por recogida. Sin fecha/hora válida se rechaza, no se inventa cero.

El sobre no agrega timestamps variables al exportar: dos exportaciones sin cambios tienen idéntico contenido y orden estable por ID. Reordenar propiedades JSON no cambia la comparación de identidad/contenido. Ni importar ni exportar autentica el archivo, verifica procedencia o crea evidencia fiscal; un archivo sintácticamente válido puede ser ficticio o manipulado. Firmas y autoridad requieren otra entrega.

Versión desconocida/campos incompatibles se rechazan sin escribir y se conserva el archivo original. Un cambio de significado/campo obligatorio/estado exige otra versión y ruta de compatibilidad explícita; no modificar v1 silenciosamente. El contrato funcional global anterior sigue siendo diseño para los eventos fuera de esta recogida experimental. `tenant_id`, autorización efectiva, aprobaciones y resultados de servidor no se fingen en este corte.

Errores observables: `INVALID_FIELDS`, `EVENT_ID_CONFLICT`, `OCCURRENCE_CONFLICT`, `STORAGE_INTEGRITY` y errores nativos de IndexedDB como `QuotaExceededError`. Conservar formulario e intento si falla la transacción; corregir campos o reintentar. Si falla la apertura/actualización, no habilitar captura; cerrar otras pestañas y reabrir. Ningún error borra datos existentes. Una lectura inconsistente exige conservar el perfil para recuperación técnica; no se ofrece «reparar» eliminando registros.

## Persistencia y decisión técnica reversible

| Alternativa | Mantenimiento/licencia/versión consultada | Encaje |
|---|---|---|
| IndexedDB nativo | Estándar de navegador; sin dependencia npm ni licencia de biblioteca. Implementación depende del navegador | Transaccional y suficiente, pero requiere más manejo propio de requests/errores/fin de transacción |
| **idb** | **8.0.4**, ISC; registro npm modificado 06/10/2026, release y código disponibles en repositorio del autor | Capa pequeña de promesas con `tx.done`, índices, upgrade y callbacks de bloqueo. Elegida para este experimento con JS existente |
| Dexie | 4.4.6 consultada, Apache-2.0; registro modificado 19/10/2026; docs y proyecto activos | Más utilidades de consultas/esquemas/reactividad; no necesarias para dos almacenes y metadatos. No instalada |

No se instaló otra capa de persistencia ni un simulador de IndexedDB: integración probada con IndexedDB real de Chrome. idb y Dexie dependen de las capacidades/cuotas del navegador y no implementan permisos, sincronización ni durabilidad ante pérdida física. La elección no fija PWA frente a app nativa.

DB exclusiva `tamago:dev002:synthetic`, versión **2**. Stores `events`, `outbox`, `meta`. Índice único empresa/lote/galpón/fecha/ocurrencia. v1→v2 solo agrega `meta`; no cambia ni descarta pendientes. Esa versión de DB experimental es distinta del esquema **v1 del cuaderno**, que vive en localStorage `tamago:pilot:v1:demo|field` y nunca es leído/escrito por este experimento.

La transacción de escritura solicita durabilidad estricta y espera su finalización; no espera red ni timers dentro de ella. Reintentos idénticos no escriben otro registro. IndexedDB serializa escritores concurrentes y el índice evita repetir ocurrencias. Otro ID para una ocurrencia ya existente necesita revisión; no se deduplica solo por igual cantidad. No hay correcciones autorizadas ni borrado desde esta UI.

Service worker limitado a `/experimental/recogidas/` (o el mismo sufijo bajo otra base). Solo atiende recursos conocidos; no intercepta el cuaderno ni peticiones de negocio. Caché versionada por hash del build; no ejecuta `skipWaiting`, permite que las pestañas anteriores terminen y no borra caches viejas ni bases. La limpieza futura de cachés deberá tratarse por separado, sin tocar IndexedDB. Solicitar `navigator.storage.persist()` es opcional y puede ser denegado; no promete respaldo.

Fuentes primarias: [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API), [idb: API, transacciones y navegadores](https://github.com/jakearchibald/idb), [Dexie](https://dexie.org/docs/), [Ajv standalone](https://ajv.js.org/standalone.html), [Service Workers](https://www.w3.org/TR/service-workers/), [WebKit: políticas de almacenamiento](https://webkit.org/blog/14403/updates-to-storage-policy/). Versiones/licencias de paquetes instalados verificadas también en sus manifests/licencias y lockfile. idb señala navegadores modernos; el mínimo real de este producto requiere pruebas físicas del bundle completo, no solo la biblioteca.

## Herramientas y límites conocidos

Biome **2.6.2** (MIT/Apache-2.0): formato y preset **recommended**, exclusivamente fuente experimental, scripts, nuevo contrato y pruebas nuevas enumeradas en `biome.json`. El legado y bundle generado quedan fuera de lint, conservando la regresión mediante sus pruebas. No se reformateó la aplicación v1. Se verificó la configuración efectiva después de migrar su sintaxis; lint no sustituye tests.

Ajv **8.20.0** (MIT) se utiliza en build; el navegador recibe su validador generado, sin compilación dinámica de esquemas. esbuild **0.28.2** (MIT) empaqueta módulos; Playwright **1.62.1** (Apache-2.0) reproduce los recorridos. Licencias runtime y del validador acompañan la salida. Dependencias/transitivas fijadas con integridad en `pnpm-lock.yaml`; no se activó telemetría externa ni se añadieron acciones CI.

Persistencia depende de origen, puerto y perfil. Borrado por usuario/SO, navegación privada, cuotas, pérdida de dispositivo, reloj incorrecto y políticas Safari/Android siguen siendo límites reales. Exportar y verificar el respaldo es esencial. El experimento lee/exporta el conjunto en memoria; grandes volúmenes necesitan pruebas de capacidad y exportación por bloques antes de piloto. No cifra datos ni separa usuarios autorizados: todas las filas son sintéticas y visibles localmente. No emplear datos reales.

La captura aún no tiene lotes/asignaciones verificadas, correcciones aprobadas, incidentes, alertas de jornada por servidor, cierre/reapertura, API, copias remotas, transporte Wi‑Fi entre tablets ni acuses auténticos. El corte demuestra persistencia local y recuperación, no seguridad multiempresa ni sincronización completa.
